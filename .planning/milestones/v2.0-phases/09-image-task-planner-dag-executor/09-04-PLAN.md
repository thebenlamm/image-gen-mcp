<objective>
Close the Phase 9 verification gaps found in `09-VERIFICATION.md` by tightening `validatePlan` so dry-run really means "validated plan" and invalid DAG execution contracts cannot pass.

This plan is intentionally narrow. It does not rework the planner, executor, serializer, or MCP registration. It patches the validator and adds regression tests for the three reproduced failures:

1. `$nodes.X.output` refs must require `dependsOn: ['X']`.
2. Planner-declared `outputKind` must match the capability operation kind.
3. `IMAGE_GEN_INPUT_ROOT` must apply to `ctx.inputImages` during validation, so dry-run cannot approve unsafe `$inputs.*` paths.
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Haiku planner -> validatePlan | Planner JSON is untrusted. This plan closes two ways it could lie: refs without dependency edges and outputKind values that contradict the operation. |
| MCP caller input_images -> dry_run response | Caller-provided paths are untrusted. This plan makes validation enforce IMAGE_GEN_INPUT_ROOT before dry_run can return success. |
| validatePlan -> executeDag | Executor assumes validation already proved refs can be resolved in dependency order. This plan restores that contract. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-04-01 | Tampering | Plan refs without dependency edges | mitigate | Add `PLAN_MISSING_DEP` validation for every `$nodes.X.output` reference. The node must declare `X` in dependsOn, or the plan is rejected before execution. |
| T-09-04-02 | Tampering / Spoofing | Planner-supplied outputKind | mitigate | Add `EXPECTED_OUTPUT_KIND` map keyed by capability operation. A data op cannot spoof image output by declaring `outputKind: 'image'`. |
| T-09-04-03 | Information Disclosure | Dry-run path validation bypass | mitigate | Validate every `ctx.inputImages` value with `assertWithinInputRoot` before validation can return `ok: true`, covering `$inputs.*` refs that dry-run never resolves through capabilities. |
| T-09-04-04 | Denial of Service | Extra realpath checks on every validation | accept | The checks are bounded by the number of caller input images and are no-ops when IMAGE_GEN_INPUT_ROOT is unset. Phase 9's expected input count is small. |
| T-09-04-05 | Repudiation | Ambiguous validation failures | mitigate | Use distinct error codes (`PLAN_MISSING_DEP`, `PLAN_OUTPUT_KIND_MISMATCH`, `INPUT_PATH_OUTSIDE_ROOT`) so traces, dry-run responses, and verification can identify the exact failed contract. |

</threat_model>
