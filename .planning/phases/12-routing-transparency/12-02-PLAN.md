const MAX_PROMPT_LENGTH = 1024;

3. Exported factory `createGrokGenerateCapability(): Capability | null`:
   - Call `const provider = createGrokProvider();`
   - Return `null` if `!provider`
   - Capability object:
     - `op: 'generate'`
     - `provider: 'grok'`
     - `modelVersion: provider.defaultModel`
     - `constraints: { requiresInputImage: false, supportsMultipleInputs: false, maxPromptLength: MAX_PROMPT_LENGTH, supportedSizes: ['square', 'landscape', 'portrait'], outputFormat: 'png' }`
     - `cost: { perCallUsd: 0.02 }` — comment: `// approximate — based on provider pricing page 2026-05`
     - `latencyMsP50: 5000` — comment: `// approximate — based on provider pricing page 2026-05`
     - `quality: { unscoredJustification: 'v1 text-to-image provider in production via generate_image; routing parity with v1 surface is a transparency gate, not a quality gate. Eval cases pending future milestone.' }`
     - `async invoke(input)`:
       a. `const prompt = input.params.prompt;`
       b. If `typeof prompt !== 'string' || !prompt.trim()` throw `new CapabilityInvokeError('CONSTRAINT_VIOLATION', 'generate requires params.prompt', false)`
       c. If `prompt.length > MAX_PROMPT_LENGTH` throw `new CapabilityInvokeError('CONSTRAINT_VIOLATION', 'generate prompt exceeds Grok max length 1024', false)` — THIS IS REQUIRED because image_op bypasses planner-side constraint checks
       d. Try: `const result = await provider.generate({ prompt, size: input.params.size as 'square' | 'landscape' | 'portrait' | undefined });`
       e. Catch: if `error instanceof CapabilityInvokeError` re-throw; else throw `new CapabilityInvokeError('PROVIDER_FAILURE', error instanceof Error ? error.message : String(error), true)`
       f. Return `{ kind: 'image', buffer: result.buffer, model: result.model, metadata: { prompt, provider: 'grok', modelVersion: result.model, qualityMeasured: false } }` — NO revisedPrompt (Grok doesn't return one)

Note: Even though Grok's v1 provider has `supportsSize = false` and ignores the size param internally, the v2 capability still declares `supportedSizes: ['square', 'landscape', 'portrait']` to match v1 generate_image's tool surface. The v1 provider silently ignoring size is a documented behavior we don't change here.
