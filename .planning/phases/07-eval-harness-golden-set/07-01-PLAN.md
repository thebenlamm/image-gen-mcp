<locked_decisions>
- Use local generated PNG fixtures committed under `eval/fixtures/`; no network calls and no generated images are required to create the golden set.
- Fixture PNGs must be small, deterministic, and produced from checked-in code or explicitly committed binary files.
- `extract_subject` local cases are required to run by default because `@imgly/local` has no API key requirement.
- `edit_prompt/openai` cases are included in `eval/cases/edit-prompt.json`, but execution is skipped with `status: "skipped"` unless `OPENAI_API_KEY` resolves to a non-placeholder value.
- The eval result format is JSON only. Do not add dashboards, HTML reports, or persistent databases.
- OCR scoring is represented by a scorer named `ocr_text_presence` with deterministic input/output contract. Until Phase 8 adds `tesseract.js`, it may return `status: "skipped"` with reason `"ocr dependency unavailable"` rather than failing the run.
- All fixture and result paths are local filesystem paths; no base64 image data belongs in result JSON.
</locked_decisions>
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Eval case JSON -> runner | Case files are local repo data but can still contain bad fixture ids or unsupported scorer names |
| Eval runner -> capability.invoke | Cases invoke real capability code, including local filesystem reads and optional provider HTTP calls |
| Eval runner -> filesystem | Runner writes artifacts under eval/results and temporary output dirs |
| Env -> provider availability | OPENAI_API_KEY may be absent, placeholder text, or invalid |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | Case file references `../../` fixture path | mitigate | `loadFixtures()` must resolve fixture paths relative to `eval/fixtures/`, reject absolute paths, reject `..` segments, and verify resolved paths start with the fixture root. |
| T-07-02 | Tampering | Result writer overwrites arbitrary path | mitigate | `writeEvalResults()` owns the output path and always writes to `eval/results/<timestamp>.json`; no caller-provided result path. Use `fs.mkdir({ recursive: true })` and atomic write via `writeFileAtomic`. |
| T-07-03 | Information Disclosure | Eval result captures prompts and local paths | accept | Personal MCP scope. Store only fixture ids, case ids, provider/op, output artifact path, score values, model, and skip/error messages. Do not store API keys, base64 image data, or full env. |
| T-07-04 | DoS | Eval accidentally calls paid OpenAI cases without key guard | mitigate | Case execution for `edit_prompt/openai` must call a `hasUsableEnv('OPENAI_API_KEY')` helper before invoking the capability. If unavailable, mark each case skipped and do not call `capability.invoke`. |
| T-07-05 | Repudiation | Future planner cannot tell which model was scored | mitigate | Each result entry must include `modelVersion` copied from the capability at execution time. |
| T-07-06 | DoS | Scorer throws on malformed/non-image output and aborts whole eval run | mitigate | Catch per-case scoring errors; record case `status: "error"` and continue remaining cases. Overall command exits 0 if the harness completed and at least one case was scored, exits 1 only for harness/config errors. |

Blocking severity threshold: high. T-07-01, T-07-02, T-07-04, and T-07-06 must be implemented exactly.
</threat_model>

```ts
export function hasUsableEnv(name: string): boolean
export async function runEval(): Promise<string>
```

Behavior:
1. `hasUsableEnv(name)` returns false when `process.env[name]` is undefined, empty, whitespace, or an unresolved placeholder matching `/^\$\{[^}]+\}$/`.
2. `runEval()` loads fixtures and cases, then iterates cases in file order.
3. For every case:
   - If any `requiredEnv` value fails `hasUsableEnv`, append an `EvalCaseResult` with `status: "skipped"`, `scores: []`, and `error: "missing required env: <names>"`.

5. Write the JSON via `writeEvalResults()` and return the result path.
6. If all cases are skipped or errored and no score has `status: "scored"`, throw `new Error("eval completed without scored cases")`.
