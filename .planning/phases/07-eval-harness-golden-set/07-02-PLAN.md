<locked_decisions>
- Quality score keys are scorer ids: `alpha_coverage`, `pixel_delta`, and `ocr_text_presence`. Aggregate per scorer by arithmetic mean over scored cases for the same `(op, provider, modelVersion)`.
- Do not assign `quality.scores` from skipped or errored cases.
- If a result's `modelVersion` does not equal the registered capability's `modelVersion`, do not apply it.
- `quality.evaluatedAt` is the eval run's `generatedAt`.
- `quality.evalResultPath` is set when the caller provides a result path to `applyEvalResultsToRegistry`; otherwise it remains undefined.
- The production-routing guardrail is registry-level. Existing first providers can register without scores during bootstrap; adding a second provider for an op must require scores unless `allowUnscoredProduction: true` is explicitly set for tests/development.
- Do not change the `ImageProvider` interface or v1.0 provider registry.
</locked_decisions>
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Eval result JSON -> registry | Result files can be stale, malformed, or for a different model version |
| Capability registration -> future planner | Registry quality metadata will influence automated routing in Phase 9 |
| Development/test fakes -> production guardrail | Tests need fake capabilities but production routing cannot silently accept unscored alternatives |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07 | Tampering | Stale eval JSON applied after modelVersion changes | mitigate | `applyEvalResultsToRegistry` only applies scores when `result.modelVersion === capability.modelVersion`; registry still clears quality on model change. |
| T-07-08 | Tampering | Skipped/error cases inflate quality | mitigate | Score aggregation only includes `EvalCaseResult.status === "scored"` and `EvalScore.status === "scored"` with finite numeric values. |
| T-07-09 | Repudiation | Future planner cannot trace score provenance | mitigate | Set `quality.evaluatedAt` and `quality.evalResultPath` when applying scores. |
| T-07-10 | Elevation of Privilege | New provider for existing op registers without scores and becomes routeable | mitigate | Registry `register()` throws by default for second providers on the same op without `quality.scores`, unless explicit `allowUnscoredProduction: true` option is passed. |
| T-07-11 | DoS | Strict guardrail blocks tests and local fakes | mitigate | Add `CapabilityRegistrationOptions` with `allowUnscoredProduction?: boolean`; tests and eval fakes can opt in explicitly. Built-ins remain first providers or receive applied scores after eval. |

Blocking severity threshold: high. T-07-07, T-07-08, and T-07-10 are blocking.
</threat_model>

  <action>
Create `src/eval/apply-results.ts` for turning result JSON into capability quality metadata.

Required exports:
```ts
export function scoresFromEvalResult(result: EvalRunResult, op: CapabilityOp, provider: string, modelVersion: string): Record<string, number> | undefined
export function applyEvalResultsToRegistry(registry: CapabilityRegistry, result: EvalRunResult, resultPath?: string): void
```

Behavior:
1. `scoresFromEvalResult` filters to result entries where:
   - `entry.op === op`
   - `entry.provider === provider`
   - `entry.modelVersion === modelVersion`
   - `entry.status === "scored"`
2. For those entries, aggregate only scores where:
   - `score.status === "scored"`
   - `typeof score.value === "number"`
   - `Number.isFinite(score.value)`
3. Return undefined if no numeric scored values exist.
4. Aggregate by scorer id using arithmetic mean.
5. `applyEvalResultsToRegistry` iterates over `registry.list()`. For each capability:
   - Get aggregate scores for `(op, provider, modelVersion)`.
   - If no scores, leave `capability.quality` unchanged.
   - If scores exist, re-register the capability with:
     ```ts
     quality: {
       scores,
       evaluatedAt: result.generatedAt,
       evalResultPath: resultPath,
     }
     ```
     and use `{ allowUnscoredProduction: true }` only if needed to overwrite an existing unscored first provider during score application.
6. Export `apply-results.ts` from `src/eval/index.ts`.

Tests:
- Applying a result with two alpha scores of `0.2` and `0.6` sets `quality.scores.alpha_coverage === 0.4`.
- A skipped case does not create scores.
- A result with mismatched `modelVersion` does not modify quality.
- Applying scores sets `evaluatedAt` and `evalResultPath`.
  </action>
