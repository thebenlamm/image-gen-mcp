<verification_gap>
`07-VERIFICATION.md` failed this observable truth:

Programmatic scorers (pixelmatch DeltaE for edits, alpha coverage for extract, OCR round-trip for text-bearing edits) run without manual intervention.

Blocking findings:
- `src/eval/scorers.ts` has `scoreOcrTextPresence()` returning `status: "skipped"` with reason `"ocr dependency unavailable"`.
- `src/eval/scorers.ts` counts `alpha > 0 && alpha < 255`, so opaque foreground masks score as zero alpha coverage.
- `eval/cases/edit-prompt.json` requests `ocr_text_presence` but does not provide `params.expectedText` for text assertions.
</verification_gap>

<locked_decisions>
- Use `tesseract.js` version `^7.0.0` as an eval dependency. `npm view tesseract.js version` returned `7.0.0` during planning on 2026-05-02.
- Keep OCR scoring inside `src/eval/scorers.ts`; do not implement the Phase 8 `analyze_ocr` capability in this plan.
- OCR text matching is case-insensitive and whitespace-normalized. The normalized OCR text must contain the normalized expected text to score `1`; otherwise score `0`.
- If `expectedText` is missing or blank for an OCR scorer, fail fast with `status: "error"` from `scoreOcrTextPresence()` and loader validation should prevent committed case files from reaching invocation.
- Keep eval result JSON shape unchanged. Do not add base64 image data, prompts, or OCR full text to result JSON.
- Do not address CR-02 artifact overwrite in this plan; verification classified it as follow-up debt that does not block the Phase 7 goal.
</locked_decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Eval output image -> OCR engine | OCR processes provider/local generated images and can be slow or fail on malformed files |
| Eval case JSON -> paid provider invocation | Bad scorer metadata must fail before paid `edit_prompt/openai` calls |
| OCR text -> result JSON | OCR content may include prompt-derived text or noisy extraction output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-------------|-------------|-----------------|
| T-07-12 | DoS | tesseract OCR worker | mitigate | Run OCR once per OCR scorer call, terminate the worker in a `finally` block, and convert OCR failures into a case-level scorer error instead of hanging the eval process. |
| T-07-13 | Tampering | OCR-backed case missing expected text | mitigate | `loadEvalCases()` must reject any case containing `ocr_text_presence` unless `params.expectedText` is a non-empty string. |
| T-07-14 | Information Disclosure | OCR scorer stores recognized text | mitigate | Do not include full OCR output in `EvalScore.reason` or result JSON. Reason strings may say `expected text not found` but must not include extracted text. |
| T-07-15 | DoS | Unsupported scorer typo discovered after provider call | mitigate | Validate scorer ids in `loadEvalCases()` against `alpha_coverage`, `pixel_delta`, and `ocr_text_presence` before any capability invocation. |

Blocking severity threshold: high. T-07-12, T-07-13, and T-07-15 must be implemented exactly.

```ts
let coveredAlphaPixels = 0;
const totalPixels = info.width * info.height;

for (let index = channels - 1; index < data.length; index += channels) {
  const alpha = data[index];
  if (alpha > 0) {
    coveredAlphaPixels += 1;
  }
}

return {
  scorer: 'alpha_coverage',
  status: 'scored',
  value: clamp01(coveredAlphaPixels / totalPixels),
};
```
